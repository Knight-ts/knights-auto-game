# Knights Auto Game

基于 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 的《诸神皇冠 / 百年骑士团》网页版自动化助手。

> **Knights Auto Game** 是 [MAAGC](https://github.com/KhazixW2/MAAGC)（MIT）的网页版衍生重写（非官方）。
> Agent、Pipeline 与资源等部分代码**借鉴自 MAAGC**，后端改为用 Python 直接驱动 MaaFramework、浏览器作为控制台，
> 不包含 MFAAvalonia 等桌面 UI。来源、上游与第三方素材说明见 [UPSTREAM.md](UPSTREAM.md)、[NOTICE](NOTICE)。

## 功能

- **主页**：模拟器搜索 / 连接、资源与 Agent 状态、最近日志，以及「场景处理」总表（月度循环会遇到的画面 → 识别条件 → 处理逻辑）
- **任务**：读取 interface.json 的任务与选项（开关 / 多选 / 下拉 / 文本），组合 pipeline_override 执行与停止，记录最近任务
- **推年计划（任务组合）**：把任务模块按顺序串成组合，设置循环次数，命名保存（如 紫砂盾循环 / 成长试炼循环 / 瓦国任务循环）并一键运行
- **截图**：设备实时画面（2 秒刷新、可下载）
- **日志**：调度日志 + Agent 输出，可清空
- **好娃提醒**：组合列表（一行一个，点「详情」展开填写）+ 按种族分类的完整特性表，保存时同步条件表 / 检测节点 / 界面选项
- **孩子记录**：查看 table/child_records.xlsx 对应记录，可标记已招募
- **佣兵记录**：智能接受佣兵（按名字白/黑名单）、记录佣兵名字与游戏年月
- **通知**：飞书 / 通用 JSON 推送配置与测试发送
- **问题自纠**：报错时自动保存现场截图 + 日志尾巴，用户判断「保留 / 删除」，可一键清空；AI 修复默认关闭，避免消耗 token

## 环境

- Windows 10/11（x64）
- Python 3.12
- **MuMu 模拟器 12（目前仅适配 MuMu）**：其他模拟器与真机未适配、未验证
- 依赖见 requirements.txt（maafw 5.12.3、opencv-python、numpy、loguru、jsonschema）

## 快速开始

项目目录内已带 `python\` 运行时（约 380 MB，已在 `.gitignore` 中排除），**双击 `启动网页版.bat` 即可离线运行**。

如果需要自己重建环境（例如换机器/更新依赖）：

1. 安装依赖：双击 安装依赖.bat（会在 .venv 里安装），或手动：

   ```bat
   python -m venv .venv
   .venv\Scripts\python -m pip install -r requirements.txt
   ```

2. 启动：双击 启动网页版.bat（优先用 `python\`，其次 `.venv`）
3. 浏览器打开 <http://127.0.0.1:8790/>（端口占用会顺延）

启动后会自动连接上次使用的模拟器并拉起 Agent；也可以在主页手动「重新搜索 → 连接设备 → 启动 Agent」。

## adb 说明

- tools/adb/adb.exe 随仓库分发（Android platform-tools，Apache-2.0），脚本、诊断与旧控制台直接调用它；
- MaaFramework 的 ADB 控制器仍使用模拟器自带的 adb（如 MuMu 的 nx_main/adb.exe）：MuMu extras 只认官方安装路径，换成项目内 adb 会让截图从约 13 ms 退化到约 250 ms。

## 任务包（tasks/）

`interface.json` 里的每个任务在 `tasks/<entry>/` 有一个文件夹：

- `task.json`：任务定义（名称、entry、勾选的选项、说明、文档）；
- `run.py`：单独运行这个任务，方便改完立刻测试；
- `index.json` 控制任务顺序，`_options.json` 存放所有选项定义。

```bat
python tools\taskpack.py export --force        :: interface.json -^> tasks\
python tools\taskpack.py build                 :: tasks\ -^> interface.json
python tools\taskpack.py check                 :: 检查任务/选项/pipeline 引用
python tools\taskpack.py pack CastleMarryTest  :: 打成 dist\tasks\CastleMarryTest.zip
python tools\taskpack.py unpack 路径.zip --build
python tasks\CastleMarryTest\run.py --set 联姻方式=联姻
```

也可以双击 `tools\任务包.bat` 用菜单操作，或网页版「任务 → 任务包」点按钮。详细说明见 [tasks/README.md](tasks/README.md)。

## 推年计划（任务组合）

「推年计划」页把任务列表里的模块（启动游戏、每日礼包、月度循环、自动相亲、战斗任务主动……）按顺序串起来，组成一套流程：

- **组合名 + 简介**：例如 紫砂盾循环、成长试炼循环、瓦国任务循环，简介写清这个组合是干什么的；
- **循环次数**：0 = 一直循环到手动停止，1 = 只跑一遍；
- **步骤**：选模块 → 添加，可上移 / 下移 / 删除；点步骤上的「选项」就地展开该模块的参数（例如自动相亲的相亲爵位、月度循环的刷取任务国家 / 成长试炼难度 / 海盗事件处理），每个步骤各存各的，互不影响；
- **自动处理规则**：遇到情况做什么——
  - 触发条件：任务失败 / 好娃提醒 / 海盗事件 / 设备离线 / 每轮结束；
  - 处理动作：重试当前步骤（N 次）/ 跳过当前步骤 / 停止组合 / 继续下一步 / 发送通知 / 重连后重试 / 等待（N 秒）；
  - 没配规则时的默认行为：任务失败停止、好娃提醒停止、海盗事件停止、设备离线停止；
- 组合保存在 `table/task_combos.json`，可随时保存、改名、删除，重启后仍在；
- 「运行组合」会按顺序执行并显示第几轮 / 第几步，按规则自动处理，可随时停止；
- **场景确认**：战斗前会确认是否还在「战斗准备」页并自动点「战斗开始」；战斗结算、城市搜索、回大地图时遇到孩子出生/命名、佣兵加入、提示弹窗会先处理再重试；组合步骤失败后会先跑一次 `SceneGuard`（最多 2 次），确认不是场景错位后才按失败规则停止/重试。

好娃提醒触发时，Agent 会写 `temp/child_alert.json` 标记，组合据此执行「好娃提醒」规则（默认停止并提示手动处理）。海盗事件则看月度循环的「海盗事件处理」选项：选「停下等手动」时 Agent 不开战，写 `temp/pirate_alert.json` 并暂停，组合按「海盗事件」规则处理（默认停止），你调整好阵容再手动打或重新运行组合。原来的整月推年流程保留为任务模块 **月度循环（原推年计划）**，可以直接放进组合里，也可以单独运行。

## 场景处理（主页）

主页新增一栏 **场景处理（月度循环）**，把月度循环里会遇到的所有画面列成一张表：

- **场景**：佣兵加入 / 生娃 / 夭折、告白成功 / 失败、婚礼、提示弹窗、佣兵退休、海盗、城堡被攻打、旅行确认、丰收节相关（口粮预交 / 年度结算 / 祈祷）、启航节、相亲、战斗准备 / 失败、场景确认、未知界面、好娃提醒、城堡资源低于阈值……
- **识别条件**：触发这条处理时要看到什么（OCR 文案 / 模板 / 节点名）；
- **处理逻辑**：命中后做什么（点哪个按钮、走哪条链、什么时候暂停）；
- **返回**：这个画面回大地图走哪几步（`table/return_routes.json`），没单独配的场景由它自己的处理函数返回；
- **源码**：点处理函数名（或「源码」）直接看函数体 / pipeline 节点定义，并能用 VS Code / Cursor 定位到行；
- **任务入口**：能单独跑的，点「去任务」直接跳到对应任务，方便停在那个画面上调试。

数据在 `table/scene_rules.json` + `table/return_routes.json`，页面通过 `GET /api/scenes` 读取；支持按类别筛选和关键字搜索，下方「最近命中」显示日志里最近的场景事件和上一次场景确认结果。实际执行仍以 agent 代码 / pipeline 节点为准，这张表是总览和索引。

### 未知界面：先点几次，没变化才记录

认不出来的画面（不是大地图、不是已知事件 / 战斗 / 检查点）不再直接判失败，而是按 **`table/return_routes.json` 的默认路线**点最多 3 次安全位置：

| 顺序 | 点哪里 | 为什么 |
|---|---|---|
| 1 | 屏幕下方 `360,1010` | 「确定 / 继续」最常见的位置 |
| 2 | 安卓返回键（keycode 4） | 大部分弹窗 / 子页面都能退 |
| 3 | 屏幕中心 `360,640` | 某些页面把按钮放在中间 |

每点一步都会重新截图，用 **32×32 灰度指纹的平均绝对差** 和点击前比较：**画面一变就停手**，交回上层重新识别（可能已经回到大地图，或进入了另一个已知画面）。三步都没有变化才记录：

- 记录写到 `debug/unknown/`（`index.json` + `snapshots/<id>/screen.png` + `meta.json` + `REPORT.md`）；
- 记录里带 **截图、点过哪些位置 / 有没有变化、当时在跑哪个任务、以及出现未知画面的调用栈（文件:行 函数）**；
- 同一画面（指纹相同）只留一条记录，重复遇到就累加「命中次数」；
- 记录完就停止恢复 / 停止这一步，不再盲点，等你在网页上处理。

网页「主页 → 场景处理 → 未知界面」可以看截图、点来源直接跳到源码、给这条记录选返回方式并写备注。选好的路线会以 `unknown:<画面指纹>` 存回 `table/return_routes.json`，**agent 下次遇到同一画面会直接照这条路线点**，不用重新试错。

返回方式也可以直接改表 / 用命令行：`python tools/unknowns.py list`、`show <id>`、`route <id> popup_tip`、`route <id> default`、`note <id> "..."`、`report`。完整说明见 [docs/zh_cn/未知界面与返回.md](docs/zh_cn/未知界面与返回.md)。

### 源码定位（场景表 / 未知记录 → 代码）

网页里所有「处理函数名」都是可点的：`webapp/source.py` 用 AST 现场扫描 `agent/`、`webapp/`、`tools/` 的 Python 文件，把函数 / 类 / 模块名解析成 **文件:行**；pipeline 节点名则用正则扫 `resource/base/pipeline/*.json` 的 key。弹窗里能看到代码片段，点「在编辑器打开」会优先用 `vscode://file/...:行` 协议（装了 VS Code / Cursor 即可定位行），不行再试 `code` / `cursor` 命令行，最后用资源管理器选中文件。行号是现场算的，代码改了也不会过期。

### 口粮预交：只在粮食充足时点确定

丰收节 / 年末的「口粮预交」面板现在会先判断粮食：

| 面板表现 | 判断 | 处理 |
|---|---|---|
| 显示「粮食充足」 | 充足 | 点「确定」提交 |
| 没有「粮食充足」（或出现「预交粮食不足」提示） | 不足 | **不点确定**：写 `temp/ration_short.json`、推送 + 弹窗、暂停任务 |
| 没读到「粮食充足」，但读到「拥有 / 消耗」数字 | 拥有 ≥ 消耗 → 充足，否则不足 | 充足点确定；不足同上 |
| 两者都读不到 | 判断不了 | 按不足处理，暂停等手动确认 |

粮食不足时点确定会扣士气，还会让孩子带上营养不良等负面特性，所以宁可停下来补粮，也不盲点。暂停后面板会留在原位，调配 / 买粮后重新运行即可。

### 丰收节·年度结算：默认点确定

识别到「年度结算」界面（标题「年度结算」；收入页显示城堡银币收入 / 占堡产出，支出页显示训练所支出 / 总支出 / 工资）时**默认点「确定」**，结清训练所支出与佣兵团成员工资后回大地图；页面上的「银币充足 / 银币不足」只作提示，不做额外判断。事件扫描、丰收节结算链、场景确认、年度恢复都会处理这个画面。

## 问题自纠（报错截图）

任务失败、任务异常、Agent 抛异常 / 启动失败 / 意外退出、接口 500、页面脚本报错，都会在**报错那一刻**抓一张设备截图，连同任务名、错误文字、最近日志一起存到 `debug/errors/`：

```
debug/errors/
  index.json                 全部记录（状态 / 错误 / 备注 / 截图路径）
  REPORT.md                  自动生成的复盘报告
  snapshots/<id>/            screen.png + meta.json + logs.txt
  trash/<id>/                用户删除的记录（可恢复，按设置自动清理）
```

网页「问题自纠」页：

- 左侧列表看缩略图、来源、时间和错误摘要；右侧看完整截图、错误、日志；
- 每条可以标 **保留**（值得修）/ **待判定** / **删除**（进回收站），也可以写备注说明哪里不对；
- 「立即抓取当前画面」可手动存一张；「设置」里调条数、体积、保留天数、去重窗口；
- 「一键清除全部」会删掉所有报错截图和记录（含回收站，需确认），适合排查完/换任务时清场；
- 自动规则：默认最多 200 条 / 400 MB，待判定 7 天后进回收站、回收站 3 天后彻底删除；超限时只丢最旧的待判定 / 回收站记录，**永远不动已保留的**；
- 好娃提醒是 Agent 主动暂停，不算任务失败、不抓报错截图；组合仍按「好娃提醒」规则执行（默认停止等待手动处理）；
- 设置存在 `config/webapp.json` 的 `selfheal` 节，可关掉自动截图。

## AI 修复（已关闭）

为避免持续消耗 token，网页版默认**关闭** AI 修复，只保留报错截图、错误记录、备注、筛选和一键清除。

- 「问题自纠」页不显示 AI 修复按钮/设置；
- 服务端不会启动 AI 修复调度线程；
- `/api/repair/*` 在关闭状态下会拒绝执行；
- 相关代码保留在 `webapp/repair.py`、`webapp/dsh_bridge.py`，以后需要时可在 `config/webapp.json` 的 `repair` 节手动启用，但启用后会真实启动 DSH 会话并消耗 token。

给 DeepSeek Harness 的入口（不需要开网页）：

```bat
python tools\selfheal.py list --status kept --json   :: 只看用户确认有价值的（含 image_path）
python tools\selfheal.py show <id>                   :: 错误 + 日志 + 截图路径
python tools\selfheal.py keep <id> --note "第 3 步识别不到按钮"
python tools\selfheal.py report                      :: 打印 REPORT.md
python tools\selfheal.py clear --yes --all           :: 一键清除全部截图与修复状态
```

约定：**保留** = 用户确认值得修，优先据此改代码；**待判定** = 还没看；**已删除** = 用户认为没价值，不要据此修复。

## 配置

- interface.json：任务列表与选项（由 `tasks/` 重建，网页版任务页直接读取）
- tasks/：任务的源文件；改完运行 `build` 再重启 Knights Auto Game 生效
- table/child_alert_conditions.json：好娃提醒条件（也可在网页“好娃提醒”页编辑）
- table/return_routes.json：未知界面的默认点击步骤、各场景 / 各记录的返回路线（网页「未知界面」可改）
- table/notify_config.json：平台推送；默认关闭，webhook 留空时复用 config/config.json 的飞书地址
- config/webapp.json：上次设备 / 任务 / 选项、问题自纠设置（`selfheal` 节）、AI 修复设置（`repair` 节，自动生成，不要提交）

## 好娃提醒怎么配组合

网页「好娃提醒」页（或原生窗口）分两块：

1. **完整特性表（按种族分类）**：26 个分类 / 214 项特性。
   - 血统：佩尔弗因王族、高等精灵、黑暗精灵等 15 个血统，带等级、部位、效果、寿命；
   - 平民血：加尔提斯人、古特人、萨尼德人等 7 个种族；
   - 通用：正面 / 中性 / 负面 / 表白怀孕特性。
   左侧点种族，右侧点「＋ 加入」，特性就加到当前组合里（再点一次取消）。搜索框可跨种族按特性名 / 效果筛选。
2. **组合列表**：每行约 2cm，显示组合名、种族标签、特性、属性门槛摘要；点「详情」展开填写界面显示名、内部 ID、条件名、检测节点、说明、**备注**、必需特性、属性门槛和或条件。备注只给自己看，会存进 `table/child_alert_conditions.json`。

「从特性表挑」会把加入目标切换到当前组合并展开特性表；「保存并同步」会写入条件表、检测节点和界面选项，勾选状态按实例保存，需要点「同步勾选到 Knights Auto Game」并重启生效。

## 孩子命名速度（可调）

网页「好娃提醒 → 孩子命名速度」或 `table/child_name_config.json`：

| 档位 | 特性滑动上限 | 步骤等待 | 适用 |
|---|---|---|---|
| fast | 2 | 200 ms | 最快，可能漏掉需要滑动的特性 |
| normal | 5 | 500 ms | 默认 |
| slow | 8 | 800 ms | 模拟器卡顿/识别不稳时 |

日志会打印每步耗时：`角色信息识别耗时 X.Xs`、`孩子命名流程耗时 X.Xs`。

## 佣兵记录与智能入队

- 任务选项「开启自动接受佣兵」选 **智能** 时生效；再打开「佣兵智能入队」（月度循环和「事件：佣兵加入」都有这个选项），就会**先点弹窗左侧「?」读角色详情**（潜力 / 人物特性 / 爵位，和「孩子命名」同一套识别）再决定收不收；
- 可配的条件（都在网页「佣兵记录」页或 `table/mercenary_rules.json` 里改）：
  - **名字**：`mode=whitelist/blacklist` + `names` 关键字；白名单留空 = 不按名字卡；
  - **入队组合**：`combos` = 勾选「好娃提醒」里的组合（特性 + 属性门槛，含 or_attributes），命中任一个就算过；
  - **必需特性**：`features` 全部命中（可留空）；
  - **属性门槛**：`potential_min={"技巧":"SS","力量":"S"}`（可留空）；
  - **爵位**：`title_min=无/骑士/男爵/伯爵/公爵`，`无` 表示不看；爵位从弹窗名字（游戏显示名带称号，机器人起名把爵位首字放末尾）和详情面板顶部一起认；
  - **橙色特性**：`min_orange=N`，0 表示不看；按 `table/各国家特性表.json` 里等级含“橙”的血统特性计数；
  - **组合方式**：`match=all` 全部满足 / `match=any` 任一满足（名字白名单 + 组合建议用 `any`）；
  - 条件的数据没读到时（面板没打开）该条件按“未启用”跳过，不会因为读不到就把人全拒；
- 名字只在弹窗里：先点地图横幅把弹窗打开，再取「希望加入佣兵团」与「年龄」两行之间的那一行，所以不会再读到上方的节日提示、“兵团”这类横幅文案；名字支持带字母和单字（如 `感S技A骑`、`宾`）；
- 接受/拒绝只会点对应按钮，不会在“取消”没反应后误点“招募”；
- 每次加入都会写入 `table/mercenary_records.csv`（时间、游戏年、游戏月、名字、结果、规则、爵位、橙色特性、属性、特性、备注）；名字没读到时写「(未识别)」，备注里保留 OCR 原文和每个条件的判定明细；
- 日志会打印 `佣兵名字取自弹窗第 NN 行：xxx（边界 a~b）`、`佣兵详情：爵位=… 特性 N 个（橙色 C），潜力 {...}`，读错时用这两行校准；
- 离线自检：`python tools/selftest_mercenary_rules.py`；
- 当前年份/月份由大地图 `C.E.xxxx` 与月份 OCR 更新到 `table/game_state.json`，孩子记录也会带游戏年月。

## 二次开发

- webapp/runtime.py：ADB 控制器、资源、Tasker、Agent 启动与任务执行
- webapp/server.py：本机 HTTP API（只监听 127.0.0.1）
- webapp/static/：页面（原生 HTML/CSS/JS，无前端构建）
- Agent 自定义动作在 agent/action/ 下，Pipeline 在 resource/base/pipeline/

## 已知限制

- **目前只适配 MuMu 模拟器 12**：依赖其 EmulatorExtras 扩展做高速截图与输入；雷电 / 夜神 / 蓝叠 / 逍遥 / 真机未测试，连接后大概率退回通用方式（截图约 250 ms），部分任务会失败
- 仅支持 Windows（依赖 MaaFramework 的 Windows 运行时与 adb）
- 同一时间只跑一个任务；没有多实例 / 定时任务
- 好娃提醒触发时会弹窗并主动暂停任务（不计为任务失败），需要手动处理后再启动
