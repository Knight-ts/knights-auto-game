# 未知界面与返回

> 实机适配于 2026-10-30。记录在 `debug/unknown/`，返回路线在
> `table/return_routes.json`；运行时实现在
> `agent/action/fight/scene_return.py`，存储 / 共用逻辑在
> `agent/utils/unknown_store.py`。

## 1. 它解决什么问题

月度循环、事件扫描、组合步骤失败后的场景确认，都可能停在一个「谁都不认识」的画面上：新活动弹窗、网络提示、没见过的子页面、被遮罩盖住的按钮。以前这类画面只有一句日志：

```
ERROR 年度流程处于未知画面，停止恢复以避免盲点
```

看不到截图、不知道点了什么、更不知道是哪一步走到的。现在的处理是：

1. **先有界地试**：按默认路线点最多 3 个安全位置；
2. **画面一变就停**：每点一步都重新截图比对，不连续盲点；
3. **真的不动才记录**：截图 + 调用栈 + 点过什么 + 识别探测，写进 `debug/unknown/`；
4. **可以配返回方式**：网页（或命令行）给这条记录选一条返回路线，下次遇到同一画面直接照做。

## 2. 遇到未知画面时到底点什么

默认路线（`table/return_routes.json` 的 `default`）：

| 顺序 | 动作 | 位置 | 为什么安全 |
|---|---|---|---|
| 1 | `click_bottom` | `360,1010` | 「确定 / 继续」最常见的位置，不会点到背包 / 商店 |
| 2 | `back_key` | 安卓返回键（keycode 4） | 关闭弹窗 / 退出子页面，不触发游戏内消费 |
| 3 | `click_center` | `360,640` | 部分页面把按钮放中间 |

> 不会去点列表、商品、确定购买、删除之类的任意坐标：未知画面上乱点可能花金币、买错东西、跳过选项。只点这三个固定位置，点不动就停下来记录。

### 怎么判断「画面有没有变化」

每次点击后重新截图，缩成 **32×32 灰度**，和点击前逐像素求平均绝对差：

- 静态弹窗：约 `0`；
- 时钟、人物走动、光效：通常 `< 2.0`；
- 真正翻页 / 关窗 / 换页：一般 `> 10`。

`差 > settings.changeThreshold`（默认 `2.0`）才算变化。变化后立刻停手，交回上层调用：

- 已经回到大地图 → 继续原流程；
- 变成了已知事件 / 战斗 / 检查点 → 按原有逻辑处理；
- 又变成另一个未知画面 → 下一轮恢复继续处理（一次恢复最多 2 轮）。

三步都点不动 → 进入记录。

## 3. 记录里有什么

```
debug/unknown/
  index.json                 记录列表（同一画面只留一条，累加命中次数）
  snapshots/<id>/screen.png  当时的画面
  snapshots/<id>/meta.json   单条完整信息
  REPORT.md                  自动生成的复盘报告（人 / Harness 都好读）
  .lock                      agent 与网页版共用的进程间写锁
```

单条记录的关键字段：

| 字段 | 含义 |
|---|---|
| `task` / `entry` | 当时在跑哪个任务（来自 `temp/current_task.json`） |
| `reason` | 为什么判定为未知（例如「按默认路线点了 3 次，画面没有变化」） |
| `attempts` | 每一步点了什么、画面有没有变、差值多少 |
| `trace` | 调用栈；**第一行就是出现未知画面的源代码位置**（`文件:行 函数`） |
| `probes` | 记录时顺手跑的识别探测：哪些节点其实命中了 / 分数多少，用来判断「是没识别，还是状态机没走到」 |
| `hits` | 同一个画面累计遇到几次（指纹相同就累加，不会刷屏） |
| `route_*` | 你选的返回方式（预设 id、步骤、标签） |

`debug/` 已被 `.gitignore` 忽略；`REPORT.md` 可以直接丢给 Harness / 粘贴到 issue。

## 4. 返回逻辑：每条记录怎么回大地图

返回路线表 `table/return_routes.json`：

```json
{
  "settings": { "maxClicks": 3, "changeThreshold": 2.0, "matchThreshold": 3.0, ... },
  "primitives": {
    "click_bottom": { "kind": "click", "x": 360, "y": 1010 },
    "back_key":     { "kind": "key",   "keycode": 4 },
    "popup":        { "kind": "task",  "task": "PopUpWindowTip" }
  },
  "default": { "label": "默认：下方 → 返回键 → 中心", "steps": ["click_bottom", "back_key", "click_center"] },
  "routes": [
    { "id": "popup_tip", "scene": "popup_tip", "label": "提示弹窗：点「确定」关闭", "steps": ["popup"] },
    { "id": "unknown:1a2b3c4d", "label": "提示弹窗：点「确定」关闭", "steps": ["popup"] }
  ]
}
```

- `scene`：对应 `table/scene_rules.json` 的场景 id，场景表的「返回」列显示它；
- `unknown:<key>`：网页给某条未知记录选好返回方式后自动写入的路线；`key` 是画面指纹摘要；
- 步骤可以直接写 `task:<节点名>`，执行时走 `context.run_task()`。

**下次遇到同一画面**：agent 先用 32×32 指纹在记录里找（差 ≤ `matchThreshold`），找到就用这条记录的 `unknown:<key>` 路线；没找到才用 `default`。所以「配一次返回方式」等于教会它这个画面怎么退。

## 5. 网页上怎么用

主页 → 场景处理 → **未知界面**：

- 左侧缩略图就是当时的画面；
- 第一行：时间、任务、命中次数、是否已配返回；
- 第二行：**来源 `文件:行 函数`**，点一下弹出源码片段，「在编辑器打开」直接定位到行；
- 「点过」：每一步是什么、有没有让画面变化；
- 「可疑识别」：记录时探测到的高分节点（可能只差一条 pipeline 分支）；
- 下拉框选返回方式 → 「保存返回方式」，写入 `table/return_routes.json`，下次生效；
- 「备注」只给自己看；「删除」删掉这条记录（不影响路线表）。

场景表每一行的处理函数名也可以直接点开源码；没有 handler 的场景按第一个识别节点定位 pipeline JSON。

## 6. 命令行 / Harness

```bat
python tools\unknowns.py list                     :: 最近记录
python tools\unknowns.py list --json              :: 机器可读
python tools\unknowns.py show <id>                :: 截图路径 + 调用栈 + 点过什么 + 探测
python tools\unknowns.py route <id> popup_tip     :: 选返回方式
python tools\unknowns.py route <id> default       :: 改回默认
python tools\unknowns.py note <id> "第 3 步弹窗"
python tools\unknowns.py report                   :: 打印 REPORT.md
```

离线自检（不需要模拟器）：

```bat
python tools\selftest_scene_return.py
```

覆盖：指纹 / 变化判断、点 3 次没变化 → 记录、同画面去重、画面一变就停、保存返回方式后按路线执行、源码定位（函数 / 类 / pipeline 节点 / 非法输入）。

## 7. 参数与调优

都在 `table/return_routes.json` 的 `settings`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉后未知画面不再点、不再记录，直接按原逻辑失败 |
| `maxClicks` | `3` | 最多点几步（1~8） |
| `clickGapSeconds` | `0.7` | 每步之后等多久再截图 |
| `changeThreshold` | `2.0` | 平均差超过它才算「画面变了」；模拟器卡顿导致误判时调大 |
| `matchThreshold` | `3.0` | 和历史记录的画面差小于它才算「同一画面」 |
| `recordLimit` | `80` | 最多保留多少条记录（有返回方式的优先保留） |
| `probeOnRecord` | `true` | 记录时是否跑识别探测（会多花几秒，但能直接看出差哪个节点） |

常见调整：

- **记录太频繁**：先把 `changeThreshold` 调到 `3.0`，模拟器的压缩噪声 / 加载动画可能被误判成没变化；
- **点了会误触**：把 `default.steps` 改成只保留 `back_key`；
- **新画面总被记录**：先看 `probes`，如果某个节点其实命中了，多半是 `_recovery_state()` / 事件扫描没走到那个分支，补分支比加返回路线更好；
- **确实只能手动退**：给它选一条能用的返回方式，或者把步骤写成 `task:<你的节点>`。
