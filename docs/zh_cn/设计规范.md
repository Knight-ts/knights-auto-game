### 宴会选择逻辑

### 用户选项覆盖（婚礼宴会档位）

任务界面的「婚礼宴会档位」可以覆盖上面的自动规则：

| 选项 | 效果 |
|------|------|
| 自动（按爵位） | 走上面的爵位规则，默认值 |
| 秘密婚礼 | 不看爵位，固定用秘密婚礼（最贵：-600 绿币 / -50 金币） |
| 简约聚会 | 不看爵位，固定用简约聚会（-150 / -30） |
| 祝福婚宴 | 不看爵位，固定用祝福婚宴（-20 / -15） |
| 乡村宴会 | 不看爵位，固定用乡村宴会（列表最下面，可能要下滑） |

- 选项存进 pipeline 节点 `MarryBanquetSelect`（`expected` = `auto` / `秘密婚礼` / `简约聚会` / `祝福婚宴` / `乡村宴会`）
- 指定档位在婚礼页找不到时，会回退到按爵位自动选的那一档，并打 warning
- 该选项对「自动相亲」「月度循环」「婚礼宴会（单项测试）」三个任务都生效（婚礼由事件触发，前两条流程都可能遇到）
- 任务列表里的「婚礼宴会（单项测试）」（`Auto_WeddingTask`）可以停在婚礼页单独跑这套逻辑、单独调档位；推年流程里由 `Event_ConfessionSuccess` 自动触发的是同一个节点 `Auto_WeddingTask`

### 婚宴确认与快捷补齐

选完档位会弹「婚宴确认」弹窗，里面按材料逐行列出「需要/拥有」：

| 情况 | 处理 |
|------|------|
| 材料都够 | 直接点「确定」，婚礼开始 |
| 缺材料 | 缺的行右侧有加号，底部还有一行「快捷补齐缺少资源」+ 加号 |

规则（按游戏实际界面）：

- 弹窗里只有**一个**加号 → 点这个加号
- 有**多个**加号 → 点**最下面**那个「快捷补齐缺少资源」的加号
- 点加号后会弹「市场供应充足，补充目前缺少的资源消耗如下：」提示，**点确定用银币补齐**（实测一次约 300 银币，不是钻石）
- 补齐后回到婚宴确认（数字变成 25/25 这种），再点「确定」，婚礼才开始，然后连点 4 下过场

节点：

| 节点 | 作用 |
|------|------|
| `Wedding_BanquetConfirm` | OCR「婚宴确认」，判断弹窗在不在 |
| `Wedding_MissingResource` | OCR「快捷补齐」，判断是不是缺材料 |
| `Wedding_FillPlus` | 模板 `Marry/plus.png`，只在最下面那行找加号（多个加号时选它） |
| `Wedding_AnyPlus` | 模板同上，整个弹窗范围找（只有一个加号时用它） |
| `Wedding_FillTip` | OCR「市场供应充足」，识别补齐后的购买提示 |

代码入口：`WeddingProcessor._handle_banquet_confirm()`（`agent/action/zshg/marry.py`），在选完档位之后、点「确定」之前调用。

- 检查时机：进入联姻大厅后、每次发送联姻请求（确认点「就这个」）后、无合适对象退出前

## 事件处理与任务

**事件处理和任务是同一个概念**：pipeline 里一条 `next` 链就是一个任务，`custom_action` 是它的处理器。所以每个事件处理器都应该在任务列表里有入口——既被自动流程调用，也能停在事件页面上单独跑、单独调选项，而不是只藏在事件扫描后面。

| 事件 | 识别节点 | 处理入口 | 任务列表入口 | 月度循环会自动处理 |
|------|----------|----------|--------------|--------------------|
| 佣兵加入 | `Event_MercenaryJoin` | `handle_mercenary_join()` / `Auto_MercenaryJoinEvent` | 事件：佣兵加入 | 是 |
| 佣兵生娃 | `Event_MercenaryBaby` | `handle_mercenary_baby()` / `Auto_MercenaryBabyEvent` | 事件：佣兵生娃 | 是 |
| 孩子夭折 | `事件_孩子夭折了` | 同节点链 | 事件：孩子夭折 | 是 |
| 丰收节事件 | `Event_HarvestFestival` | `Event_HarvestFestivalDealWith` | 事件：丰收节结算 | 是 |
| 告白成功 | `Event_ConfessionSuccess` | → `Auto_WeddingTask` | 事件：告白成功（含婚礼） | 是 |
| 告白失败 | `Event_ConfessionFail` | `handle_confession_fail()` / `Auto_ConfessionFailEvent` | 事件：告白失败 | 是 |
| 提示弹窗 | `PopUpWindowTip` | 同节点链 | 事件：提示弹窗 | 是 |
| 佣兵退休 | `Event_MercenarieRetire` | 同节点链 | 事件：佣兵退休 | 是 |
| 海盗袭击 | `Event_PirateRaid` | `Event_PirateRaid_Dispatch` | 事件：海盗袭击 | 是 |
| 3 月启航节 | `Event_Launch` | `handle_sailing_festival()` / `Auto_SailingFestivalEvent` | 节日：3月启航节 | 是（3 月） |
| 4 月城堡相亲 | — | `handle_marry_festival()` → `Auto_MarryTask` | 自动相亲 / 城堡相亲（单项测试） | 是（4 月） |
| 5 月春林节相亲 | — | `handle_marry_festival(month=5)` | 无（只有跳过 / 手动） | 是（5 月，仅跳过/手动） |
| 8 月丰收节 | — | `handle_harvest_festival()` | 无（空实现，只有日志） | 是（空实现） |
| 10 月勇士节 | — | `handle_warrior_festival()` | 无（空实现，只有日志） | 是（空实现） |
| 婚礼 | `Event_WeddingPage` | `WeddingProcessor` | 婚礼宴会（单项测试） | 是（告白成功链 + 事件扫描都会处理） |

规则：

- 事件处理器只写一份（函数或节点链），任务入口和自动流程都调它，任务里不复制逻辑。
- 新增事件时三步：写识别节点 → 写处理函数/节点链 → 加任务入口（`tasks/<entry>/task.json` + `taskpack.py build`）。
- 有选项的事件（佣兵加入、生娃、告白失败、婚礼、启航节）把选项挂在对应任务上；选项本身仍是 pipeline 数据节点，读写方式不变。

## 相亲筛选（种族 / 年龄）

### 种族：相亲种族

| 取值 | 多角色模式 | 单角色模式 |
|------|-----------|-----------|
| 不限（默认） | 不过滤，按每个候选人自己的血统决定国家（旧行为） | 回退到高阶精灵（单角色必须指定种族） |
| 具体种族 | 候选人最高血统种族 ≠ 所选种族就跳过，不点进详情后续流程 | 用它决定 `CastleMarrySelectCountry` 去哪个国家 |

- 节点：`MarryRaceSelect`（`expected` = 种族名 / `不限`）
- 判断在 `_race_matches()`，用在 `_process_single_candidate()` 读完血统之后
- 血统名先经 `_get_marriage_info()` 归一（含字形模糊匹配，如「宏朝贵胃」→「宏朝贵胄」），再和选项比较

### 年龄：相亲年龄区间

任务页填两个数字（**0 或留空 = 该侧不限**），三种用法：

| 想要的区间 | 最小年龄 | 最大年龄 |
|-----------|---------|---------|
| 小于 60 岁 | 0 | 60 |
| 60 ~ 120 岁 | 60 | 120 |
| 大于 120 岁 | 120 | 0 |
| 不限 | 0 | 0 |

- 节点：`MarryAgeMin` / `MarryAgeMax`（由 input 选项的 `{最小年龄}` / `{最大年龄}` 占位符写入）
- 列表扫描阶段就按区间跳过（`_find_available_candidates`），详情页再兜底判一次（`_check_and_filter_by_age`）
- 区间内仍然是「年龄从大到小」排序，先处理年龄大的
- 下限 > 上限时自动交换并打 warning
- 实现：`_get_selected_age_range()` / `_age_matches()`
