## 命名规则

### 孩子命名格式

孩子命名格式：`最高属性 + 次高属性 + 特性 + 爵位`

### 示例

`力 ss 技 ss 太科公`

- 力: 最高属性（力量）
- ss: 属性等级（>0.93）
- 技: 次高属性（技巧）
- 太: 特性（太阳）
- 科: 特性（科内塔）
- 公: 爵位（公爵）

## 婚礼宴会选择

### 宴会档位规则

- **公爵（等级 4）** → 乡村宴会
- **伯爵及以下** → 祝福婚宴

### 宴会选择逻辑

根据父母的爵位等级自动选择合适的宴会档位，确保婚礼效果最大化。

### 用户选项覆盖（婚礼宴会档位）

任务界面的「婚礼宴会档位」可以覆盖上面的自动规则：

| 选项 | 效果 |
|------|------|
| 自动（按爵位） | 走上面的爵位规则，默认值 |
| 乡村宴会 | 不看爵位，固定用乡村宴会 |
| 祝福婚宴 | 不看爵位，固定用祝福婚宴 |

- 选项存进 pipeline 节点 `MarryBanquetSelect`（`expected` = `auto` / `乡村宴会` / `祝福婚宴`）
- 指定档位在婚礼页找不到时，会回退到按爵位自动选的那一档，并打 warning
- 该选项对「自动相亲」「月度循环」「婚礼宴会（单项测试）」三个任务都生效（婚礼由事件触发，前两条流程都可能遇到）
- 任务列表里的「婚礼宴会（单项测试）」（`Auto_WeddingTask`）可以停在婚礼页单独跑这套逻辑、单独调档位；推年流程里由 `Event_ConfessionSuccess` 自动触发的是同一个节点 `Auto_WeddingTask`

## 相亲被拒处理

相亲回信被对方拒绝时，按任务界面的「相亲被拒处理」处理：

| 选项 | 效果 |
|------|------|
| 放弃（换下一位） | 点「放弃 / 离开」关掉弹窗，默认值 |
| 金币挽留 | 找弹窗里含「金币」或「挽留」的按钮并点击（会花金币），找不到则回退到放弃 |

- 选项存进 pipeline 节点 `MarryRejectGoldSelect`（`expected` = `giveup` / `keep`）
- 弹窗识别：`CastleMarryRejectDialog`（只识别，不点击）
- 点击节点：`CastleMarryRejectGold` / `CastleMarryRejectGiveUp`
- 检查时机：进入联姻大厅后、每次发送联姻请求（确认点「就这个」）后、无合适对象退出前

## 告白失败处理

推年途中会随机遇到「告白失败」事件（`Event_ConfessionFail`），按任务界面的「告白失败处理」处理：

| 选项 | 效果 |
|------|------|
| 放弃 | 点「放弃」结束这次告白，默认值，和改动前行为一致 |
| 金币挽留 | 找弹窗里含「金币」「挽留」「留下」的按钮并点击（会花金币），找不到则回退到放弃 |

- 选项存进 pipeline 节点 `ConfessionFailSelect`（`expected` = `giveup` / `keep`）
- 点击节点：`Event_ConfessionFailKeepGold`（金币）/ `Event_ConfessionFailGiveUp`（放弃）
- 入口：`fight_processor.handle_confession_fail()`，由事件扫描 `detect_and_manage_event()` 调用
- 点完金币按钮如果还弹确认框，会补一次 `PopUpWindowConfirm`
