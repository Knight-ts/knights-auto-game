# 连接设置

本文档详细介绍如何配置 Knights Auto Game 与游戏设备的连接。

## 📱 一、模拟器连接（推荐）

### 1.1 支持的模拟器

> ⚠️ **目前仅适配 MuMu 模拟器 12**。雷电、夜神、蓝叠、逍遥等其他模拟器以及真机均未测试：
> 它们可能仍能通过通用 ADB 方式连接，但无法使用 MuMu 的截图 / 输入扩展，
> 单次截图会从约 13 ms 退化到约 250 ms，依赖 2 秒超时节点的任务容易失败。

- ✅ MuMu 模拟器 12（当前唯一适配的目标环境）
- ❌ 其他模拟器 / 真机（未适配、未验证）

### 1.2 模拟器配置步骤

#### 步骤 1：开启 ADB 调试

**MuMu 模拟器 12**：

1. 打开 MuMu 模拟器
2. 点击右上角「菜单」
3. 选择「设置中心」
4. 进入「其他」选项卡
5. 开启「ADB 调试」
6. 记下「ADB 端口」（默认 `16384`，部分版本为 `7555`）

#### 步骤 2：获取 ADB 端口

不同模拟器默认 ADB 端口：

| 模拟器 | 默认端口 | 备注 |
|-------|---------|------|
| MuMu 12 | 16384 | 部分版本为 7555，多开时逐个递增 |

> 其他模拟器（雷电 5555、夜神 62001、蓝叠 5555 等）虽然也能 `adb connect`，
> 但不在当前适配范围内，见 1.1 的说明。

**查看端口方法**：

1. 打开模拟器设置
2. 查找"ADB 端口"或类似选项
3. 记录端口号

#### 步骤 3：验证 ADB 连接

打开命令行（CMD 或 PowerShell），输入：

```bash
adb connect 127.0.0.1:16384
adb devices
```

如果看到设备列表中有设备，说明连接成功。

### 1.3 在 Knights Auto Game 中配置

1. 双击 `启动网页版.bat`
2. 浏览器打开 <http://127.0.0.1:8790/>
3. 在主页点「重新搜索」，从设备下拉框选择 MuMu（地址形如 `127.0.0.1:16384`）
4. 点「连接设备」，状态变为已连接后再点「启动 Agent」

### 1.4 多开配置

当前版本同一时间只连接一个设备、只跑一个任务。多开需要分别启动多份程序，
每份使用独立目录（配置写在各自的 `config/` 下），端口会自动顺延：

| 实例 | MuMu ADB 端口 | 页面地址 |
|-----|---------|-----------|
| 实例 1 | 16384 | 127.0.0.1:8790 |
| 实例 2 | 16416 | 127.0.0.1:8791 |

## 💻 二、PC 端连接

### 2.1 系统要求

- Windows 10/11
- 游戏已安装并可正常运行
- 游戏窗口可正常显示

### 2.2 配置步骤

#### 步骤 1：启动游戏

1. 正常启动游戏客户端
2. 等待游戏进入主界面
3. 确保游戏窗口可见

#### 步骤 2：选择窗口

**MFAA/MXU 版本**：

1. 打开 Knights Auto Game
2. 选择控制器类型为"Win32"
3. 从下拉列表中选择游戏窗口
4. 点击"连接"

**PiCLI 版本**：

```json
{
  "controller": {
    "type": "Win32",
    "window_name": "游戏窗口标题"
  }
}
```

### 2.3 窗口要求

- 游戏窗口必须在前台运行
- 窗口不能被最小化
- 避免其他窗口遮挡游戏窗口
- 建议使用窗口模式而非全屏

### 2.4 分辨率设置

**推荐分辨率**：

- 720x1280（推荐）
- 1920x1080
- 其他 9:16 比例分辨率

**调整方法**：

1. 打开游戏设置
2. 进入"画面设置"
3. 选择合适的分辨率
4. 保存设置

## 🔍 三、连接问题排查

### 问题 1：无法连接到模拟器

**可能原因**：

- ADB 调试未开启
- 端口号错误
- 模拟器未完全启动
- 防火墙阻止连接

**解决方案**：

1. 确认模拟器已开启 ADB 调试
2. 检查端口号是否正确
3. 等待模拟器完全启动
4. 暂时关闭防火墙测试
5. 重启模拟器和 Knights Auto Game

### 问题 2：连接后无法识别画面

**可能原因**：

- 分辨率不符合要求
- 游戏语言不是简体中文
- 画面被遮挡
- OCR 资源未正确加载

**解决方案**：

1. 调整分辨率为 720x1280
2. 设置游戏语言为简体中文
3. 确保游戏窗口完整显示
4. 重新下载 OCR 资源文件

### 问题 3：连接不稳定

**可能原因**：

- 网络问题
- 模拟器性能不足
- ADB 版本过旧

**解决方案**：

1. 使用本地模拟器（127.0.0.1）
2. 增加模拟器内存分配
3. 更新 ADB 到最新版本
4. 关闭不必要的后台程序

## 🛠️ 四、高级配置

### 4.1 自定义 ADB 路径

如果模拟器自带的 ADB 不可用，可以使用系统 ADB：

**MFAA/MXU 版本**：
在设置中指定 ADB 可执行文件路径

**PiCLI 版本**：

```json
{
  "controller": {
    "type": "Adb",
    "adb_path": "C:\\path\\to\\adb.exe"
  }
}
```

### 4.2 无线连接

部分模拟器支持无线 ADB 连接：

```bash
# 启用无线调试
adb tcpip 5555

# 获取设备 IP
adb shell ip addr show wlan0

# 无线连接
adb connect 设备 IP:5555
```

### 4.3 多设备管理

使用 ADB 管理多个设备：

```bash
# 查看所有连接的设备
adb devices

# 指定设备执行命令
adb -s 设备序列号 shell

# 断开设备
adb disconnect 设备 IP:端口
```

## 📊 五、性能优化

### 5.1 模拟器优化

**CPU 设置**：

- 分配 2-4 核心
- 开启虚拟化技术（VT）

**内存设置**：

- 分配 2-4GB 内存
- 根据系统内存调整

**渲染设置**：

- 使用 DirectX 或 OpenGL 模式
- 关闭不必要的特效
- 降低帧率到 30FPS

### 5.2 系统优化

- 关闭不必要的后台程序
- 设置高性能电源模式
- 更新显卡驱动
- 确保足够的磁盘空间
