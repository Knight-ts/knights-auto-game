# 任务接取规则（按城市）

> 对应代码：`agent/utils/task_rules.py`、`agent/action/zshg/task_hud_recognizer.py`、
> `agent/action/fight/fight_utils.py`、网页面板「任务接取」。

任务接取不再使用写死的 120 级上限和一份全局黑名单，而是**按城市**配置：

- **等级区间**：每个城市可单独设置最低 / 最高等级（默认 0–120）；
- **名称黑名单**：分「全局（所有城市）」和「城市黑名单」，城市名单只在该城市生效；
- **任务列表**：每次扫描任务板都会保存快照，网页上能看到每条任务的名称、类型、
  等级、描述，以及**是否可接 / 被跳过原因**（等级、黑名单、保护任务、非战斗）；
- **任务记录**：沿用原来的按城市分组记录（接取后战斗回合数），可按城市筛选。

## 1. 数据文件

| 文件 | 作用 |
|---|---|
| `table/task_accept_rules.json` | 城市等级区间 + 城市黑名单（网页「任务接取」保存） |
| `table/task_blacklist.json` | 全局黑名单，旧格式 `{"blacklist": [...]}`，所有城市共用 |
| `table/task_pool.json` | 最近一次任务板快照（城市 / 时间 / 每条任务判定） |
| `table/task_records.json` | 按城市汇总的任务记录（次数 / 平均回合） |
| `table/task_records.jsonl` | 任务记录明细 |

规则示例：

```jsonc
{
  "defaults": { "min_level": 0, "max_level": 120 },
  "cities": {
    "暮角城": {
      "min_level": 40,
      "max_level": 90,
      "blacklist": ["观察者", "危机四伏"]
    }
  }
}
```

- `cities` 里没写的城市使用 `defaults`；
- `defaults` 改了会影响所有未单独配置的城市；
- 全局黑名单与城市黑名单取并集，**城市名单不会影响别的城市**。

## 2. 网页面板「任务接取」

1. 顶部选择城市（默认自动选中最近任务板的城市；选「全部城市」编辑默认规则）；
2. 「接取规则」填写最低 / 最高等级 → 保存，立即生效（Agent 按文件 mtime 热加载）；
3. 「最近任务板」显示最近一次扫描结果，按当前城市规则实时判定；
   - `可接` / `跳过` + 原因；
   - 右侧「拉黑」把任务名加入**当前城市**黑名单（选「全部城市」时加入全局）；
4. 「黑名单」分两块：
   - 全局（所有城市）：对所有城市生效；
   - 当前城市黑名单：只对当前城市生效；
   - 输入框回车或点「添加」即可新增，点「解除」移除；
5. 「任务记录」按城市筛选，保留原来的拉黑快捷按钮。

## 3. 接取逻辑

`_accept_new_task()` 每次执行时：

1. 读取当前城市（界面选项「选择刷取任务国家」→ pipeline 节点 `EnterCity`）；
2. 取该城市规则：`task_rules.city_rule(city)`，并合并全局 + 城市黑名单；
3. 任务板先有界回到顶部，再逐屏下滑扫描（最多 5 屏）；
4. 每屏识别所有任务图标与信息，写入 `task_pool.json`；
5. 过滤规则（与网页判定一致）：
   - 保护任务类型（`保护任务` / `保护任务1`）跳过；
   - 描述包含 `购买 / 杂货铺 / 送往 / 送到` 的非战斗委托跳过；
   - 名称命中黑名单跳过；
   - 等级低于下限或高于上限跳过；
6. 在可接任务里选**等级最高**的一条接取；
7. 整块任务板没有候选时，用页面提供的 10 水晶刷新一次再扫；
8. 接取成功写任务记录（城市 / 任务 / 类型 / 等级），战斗结束后补回合数。

## 4. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/task-rules` | 规则 + 全局黑名单 + 任务板快照 + 城市列表 |
| POST | `/api/task-rules/save` | `{city, min_level, max_level}`，`city` 为空表示默认规则 |
| POST | `/api/task-rules/blacklist` | `{city, task}`，`city` 为空表示全局 |
| POST | `/api/task-rules/unblacklist` | 同上，移除 |
| GET | `/api/task-records` | 任务记录汇总 + 全局黑名单（旧接口保留） |

## 5. 兼容性

- 旧的 `table/task_blacklist.json` 继续生效，作为全局名单；
- 旧网页接口 `/api/task-records/blacklist` 仍然写入全局名单；
- CLI / MFAAvalonia 用户可直接编辑 `table/task_accept_rules.json`；
- 没有 `task_accept_rules.json` 时全部城市使用默认 0–120 级。

- `selftest_task_web.py`：HTTP 接口与页面静态资源（不连接设备、不启动 Agent）。
